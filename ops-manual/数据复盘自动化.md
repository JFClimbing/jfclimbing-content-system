# 数据复盘自动化（抖音）

> 建立 2026-09-19 ｜ 目的：**以后不用问用户要数据，直接跑脚本**

---

## 一条命令

```bash
python3 /root/bin/dy_review.py
```

**它自动做四件事**：

1. 打开抖音创作者中心（用已有的登录态）
2. 自动滚动加载，抓到全部作品
3. 存当天快照 → `content-lab/data/dy_works_<日期>.json`
4. 打印全量表格 + 与上次快照的播放增量 + **自动对答案**

---

## 全部参数

| 命令 | 作用 |
|---|---|
| `python3 /root/bin/dy_review.py` | 抓取 + 表格 + 增量 + 对答案 |
| `python3 /root/bin/dy_review.py --table` | 同上 |
| `python3 /root/bin/dy_review.py --diff` | 只看与上次快照的播放增量 |
| `python3 /root/bin/dy_review.py --force-check` | 忽略对答案日期，强制对全部待验证预测 |

---

## 文件结构

```
/root/bin/dy_review.py          ← 主脚本（抓取 + 解析 + 对比 + 报告）
/root/bin/dy_scrape.js          ← 浏览器端抓取器（自动滚动，边滚边收）

content-lab/data/
  dy_works_<日期>.json          ← 每次抓取的快照（历史可回溯）
  prediction_registry.json      ← 预测登记表（新增预测往这里加）
```

## 怎么加一条新预测

编辑 `content-lab/data/prediction_registry.json`，往 `items` 里加：

```json
{
  "id": "ep07",
  "title": "第 7 集 · 头盔",
  "match": "头盔什么时候必须戴",
  "published": "2026-09-28",
  "check_at": "2026-09-29",
  "metrics": { "播放": 4200, "划走率": "50%" },
  "range": { "播放": [2500, 7000] },
  "status": "pending"
}
```

- `match`：标题关键词，用于在作品列表里匹配（**写最独特的那几个字**）
- `check_at`：到这天脚本就会自动对答案
- `status`：`pending` → 对完确认后改 `done`（同一集只在 registry 里记一次判定，观测池另存）

| 项 | 结论 |
|---|---|
| **幂律外推偏乐观** | 主锁 −13.1% / 主绳辅绳 −11.2%，**两次一致偏低 11-13%** |
| 修正用法 | **中枢 × 0.85**，区间下沿保持 |
| 判定 | 小幅超出区间下沿的风险要按"出区间"对待 |

## 技术要点（踩过的坑）

1. **`minis-browser-use execute_js` 返回的 `text` 尾部会附一行 `\n  tab_id: N`**
   → 解析前必须用 `json.JSONDecoder().raw_decode()` 剥掉

2. **列表是懒加载的**
   → 抓之前必须反复调用 `minis-browser-use scroll --direction down --amount 800`
     （14 次 × 800px）。**在 JS 里 `window.scrollBy` 无效**，也找不到 overflow 容器

3. **卡片选择器**：`div[class*="video-card-content"]`（class 名带随机后缀，只能用模糊匹配）
   指标：`div[class*="metric-item-container"]` → `div[class*="metric-label"]`

4. **登录态会过期**（约几小时到几天）
   → 报错时让用户重新扫码/验证码登录一次创作者中心
